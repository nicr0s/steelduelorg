# Contributing to Steel Duel

Read the [README](README.md) and [roadmap](docs/ROADMAP.md), then run the game locally before proposing a gameplay change.

## Bug reports

Include your OS, Python and Pygame versions, the keys you pressed, expected behavior, and observed behavior. A screenshot or short recording helps explain animation and collision issues.

## Changes

Keep each change focused. Describe its effect on the game and how you checked it. Update both README languages when changing controls or setup instructions.

For gameplay changes, check both fighters, attack animations, ability cooldowns, and a complete round. For asset changes, preserve included license notices and document their source. Keep generated caches, virtual environments, and editor settings out of Git.

There is no automated test suite yet. A project-wide license remains to be selected; existing asset notices are separate from the game's code.
